# MIMI OCR 0.2.1

ndlocr-lite の既定の版を 1.4.0 に戻した版です。0.2.0 で入るようになった ndlocr-lite 2.0.0 は、裁判書類の横組みの表と FAX の画質で 1.4.0 より読み誤りが多かったためです。2.x は設定で選べます。

## 配布物

- `mimi-ocr-win-x64-0.2.1-20261126-165607.zip`

## ndlocr-lite の版

- 既定を ndlocr-lite 1.4.0 にしました。PyPI には 2.x しかないので、GitHub のタグの zip から pip で入れます（git は要りません）。0.2.0 で 2.0.0 が入っている環境では、次の実行で 1.4.0 に入れ替わります。依存パッケージは入れ替え、モデル（約157MB）は初回に `%LOCALAPPDATA%\ndlocr-lite\models\v1.2` へ取ります。
- 決めた理由: 裁判書類27頁（準備書面・証拠説明書・判決、スキャン相当と FAX 相当）を ndlocr だけで読ませると、欠落は 1.4.0 が 5.03%、2.0.0 が 6.51% でした。2.0.0 は証拠説明書の表の狭い欄を崩し（4.77% → 14.79%）、もっともらしい誤った数字を出します。FAX 相当では日付を落としました。きれいなスキャンの書面・判決と縦組みの本文は同じくらいです。詳しくは `benchmark/results/2026-11-26-ndlocr-lite版の比較.md`。
- 頁に写真が入った資料を FAX の画質で読むと、1.4.0 は写真の部分に意味のない字の列を出すことがあります（2.0.0 は出しません）。0.2 の既定の読み方（頁の画像を AI が読み、ndlocr の読みは参考と照合に使う）では本文に入りませんが、ndlocr だけで読む無料の道では残ります。
- 2.x を使うときは、`config.json` の `tools.ndlocrLite.version` を `2` にするか、GUI の詳細設定の「ndlocr-liteの版」に `2` と入れてください。版を替えると次の実行で入れ替えます。
- GitHub に届かない環境では、1.4.0 の zip を手元か社内に置き、環境変数 `MIMI_NDLOCR_LITE_1_4_URL` にその URL を入れると、そこから入れます。
- `tools.ndlocrLite.repoPath` に自分で clone した ndlocr-lite を指定している場合は、これまでどおりその `src/ocr.py` を使います（`version` は効きません）。

## 互換性とアップグレード

- 出力のファイル名、ページ境界、末尾メタデータの形式は 0.2.0 と同じです。
- 旧版の ZIP へ上書きせず、新しいフォルダへ展開して `mimi-ocr.exe` を起動してください。`config.json` の API キーやモデル指定は引き継がれます。初回の ndlocr-lite の入れ替えに数分かかります。

## 既知の制限

- この配布物は Windows x64 用です。
- OCR の結果は正本ではありません。FAX の画質ではどの設定でも日付の数字を読み違えることがあるので、日付と数字は照合レポートと原本の画像で確かめてください。
- 比較は39頁の小さな試験で、手書き・古い活字・縦組みの表は含みません。
